# 면접 이론 공부 노트 (AI·RAG·백엔드 기본)

작성일 2026-11-25 · 작성자 반재영 · JobMate와 연결해 "개념 → 내 프로젝트에서는" 순서로 답하는 연습용입니다. 개념 설명은 일반적으로 알려진 내용을 정리한 것이므로, 면접 전에 본인 말로 다시 풀어 보세요.

## 1. 답변 공식
1. **한 줄 정의** 2. **왜 필요한가** 3. **내 프로젝트 적용(JobMate)** 4. **한계·대안**
행동 질문(협업·갈등·실패)은 STAR(상황·과제·행동·결과)로 답합니다.

## 2. LLM·RAG 이론

| 질문 | 핵심 답변 | JobMate 연결 |
|---|---|---|
| LLM이란? | 대량의 텍스트로 다음 토큰을 예측하도록 학습된 대규모 언어 모델. 트랜스포머 구조 | 문장 재작성에만 보조로 사용 |
| 환각이란? | 근거 없는 내용을 사실처럼 생성하는 현상. 학습 데이터 한계·확률적 생성이 원인 | 숫자·기술명 사후 검증 |
| RAG란? | 생성 전에 외부 지식을 검색해 프롬프트에 근거로 넣는 방식. 최신성·근거 제시·환각 감소 | 직무 가이드 청크 검색 |
| RAG vs 파인튜닝? | RAG는 지식 갱신이 쉽고 출처 제시 가능, 파인튜닝은 말투·형식·특정 과업 적응에 유리. 지식 주입 목적이면 RAG가 비용·갱신 면에서 유리한 경우가 많음 | 지식 파일(jobs.mjs)만 고치면 갱신 |
| 청킹이란? | 문서를 검색 단위로 자르는 일. 너무 크면 노이즈, 너무 작으면 문맥 손실 | 의미 단위 4종×13 + 공통 8 |
| BM25? | TF·IDF·길이 보정 기반 어휘 검색. 빠르고 설명 가능, 동의어에 약함 | 기본 검색기 |
| 임베딩·코사인 유사도? | 문장을 벡터로 바꿔 의미 가까움을 방향 유사도로 측정. 동의어에 강하나 모델 필요 | 선택 기능(하이브리드 0.5:0.5), 실측 못함 |
| 하이브리드 검색? | 어휘 + 의미 점수를 섞어 재현율·정밀도 보완 | 같음 |
| 프롬프트 인젝션? | 입력 문서 속 지시로 모델 행동을 바꾸려는 공격. 입력을 데이터로 취급, 출력 검증, 권한 최소화 | 시스템 프롬프트 + 검증 + 텍스트만 렌더 |
| temperature? | 샘플링 무작위성. 0이면 거의 결정적 | 0 사용(재현성) |
| 토큰·컨텍스트 윈도우? | 모델이 한 번에 처리하는 입력 단위·한도 | 문서 앞 1,500자만 프롬프트에 |
| 평가 지표(Top-k, F1)? | Top-k: 정답이 상위 k에 있는 비율. F1: 정밀도·재현율 조화평균 | Top-1/Top-3 |
| 과적합? | 학습/튜닝 데이터에 지나치게 맞아 새 데이터에서 성능 저하 | 가중치를 같은 평가셋으로 고른 한계 |
| 데이터 누수? | 평가 정보가 학습·튜닝에 섞여 성능이 부풀려짐 | 어려운 셋 추가로 점검 |
| ablation? | 구성요소를 하나씩 빼 기여를 확인 | 사전만/RAG만/전체 비교 |

## 3. ML·딥러닝 기본
- **지도·비지도·강화학습**: 정답 라벨 유무와 보상 구조로 구분.
- **과적합 방지**: 데이터 증강, 정규화, 조기 종료, 교차검증, 모델 단순화.
- **분류 지표**: 정확도(불균형에서 함정), 정밀도(예측 중 맞은 비율), 재현율(실제 중 찾은 비율), F1, AUC.
- **CNN/RNN/Transformer**: 이미지 지역 패턴 / 순서 데이터 / 어텐션으로 전체 문맥 병렬 처리.
- **전이학습·파인튜닝**: 사전학습 모델을 소량 데이터로 적응.
- **MLOps**: 모델 버전·서빙·모니터링·재학습 자동화.

## 4. 백엔드·DB·웹 기본

| 주제 | 핵심 |
|---|---|
| REST | 자원(URL)+메서드(GET/POST), 무상태, 상태 코드(400 잘못된 요청/404/413/429/500) |
| 트랜잭션·ACID | 원자성·일관성·격리성·지속성. 부분 실패 시 ROLLBACK |
| 인덱스 | 조회 속도↑, 쓰기·공간 비용↑. 자주 조회하는 컬럼에 |
| 정규화 | 중복 제거·이상 현상 방지, 조회 시 조인 비용 |
| 외래키 | 참조 무결성. SQLite는 `PRAGMA foreign_keys=ON` 필요 |
| UPSERT vs REPLACE | UPSERT는 갱신, REPLACE는 삭제 후 삽입(FK 위반 가능) → 실제 겪은 버그 |
| N+1 문제 | 반복 쿼리로 성능 저하 → 조인/배치 |
| 동기·비동기 | Node.js는 단일 스레드 이벤트 루프, I/O는 비동기(async/await) |
| 캐시 | 반복 계산·조회 결과 저장(임베딩 캐시 파일) |

## 5. 보안 기본
- **XSS**: 입력을 HTML로 삽입해 스크립트 실행 → innerHTML 대신 textContent, CSP.
- **SQL 인젝션**: 문자열 연결 대신 바인딩 쿼리(prepare + ?).
- **IDOR**: 남의 ID로 자원 접근 → 모든 조회에 소유자 조건.
- **경로 이탈**: `../`로 서버 파일 접근 → 정규화 후 허용 폴더 검사.
- **비밀 관리**: 키는 환경변수, 로그·응답에 비노출, .gitignore.
- **개인정보 최소 수집·마스킹**, 전송 구간 HTTPS(공개 배포 시 필수).
- **레이트 리밋**: 남용·비용 보호(429).

## 6. 설계·테스트 기본
- **관심사 분리**: http / 업무 / 저장 / 외부 호출을 나눠 테스트·교체 용이.
- **어댑터·의존성 주입**: 외부 의존을 인터페이스 뒤에 숨기고 테스트에서 가짜로 교체.
- **테스트 피라미드**: 단위 많이, 통합 적당히, E2E 적게. 회귀 테스트로 재발 방지.
- **재현성**: 같은 입력→같은 결과(규칙 기반, temperature 0).
- **Git**: 브랜치·커밋 단위, 의미 있는 메시지, 충돌 해결.
